## Browser and visual evidence

The Codex in-app browser used a loopback-only server serving the production build with the repository's domain-backed synthetic API. Desktop widths 1280 and 1440, a 390 px narrow viewport and 320 px reflow were inspected. Overview, Cash Desk and public Help had no page-width overflow in the checked narrow states. The 320 px check is a CSS reflow check, not a physical phone or native 400% browser-zoom claim. Native zoom shortcuts did not change the embedded browser's scale, so native zoom remains an independent check.

Keyboard checks included menu search, first Escape clearing its query, second Escape closing the drawer and returning focus to Menu; optional guide dismissal; help search/Enter and browser Back; default main focus, public-entry scroll and refresh. The document guard now restores only the outer offset, while internal main scrolling continues. The final header top and document offset were both zero after the previously failing focus/reload path. Light and dark overview states were inspected. Captured browser error logs were empty during the completed local walkthrough.
