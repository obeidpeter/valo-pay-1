# Beginner usability programme

This package records improvements that help a first-time Valo Pay user understand their workspace, choose an appropriate task, interpret its result and recover safely. The work changes the existing interface and task guidance; it does not create a new financial product or relax operating controls.

The source baseline is merged PR #78, `83eda41dba56da6dfc65a10ce3e228906de17dac`, in `obeidpeter/valo-pay`. Work is on `codex/beginner-usability-2026-09-29`. The last separately verified deployed baseline is PR #78, live build `83eda41 2026-09-29T10:26:46.692Z`; this programme is a candidate, not a new deployment. The final candidate revision, combined test results, browser evidence and remaining verification belong in [validation](validation.md). A passing test on an earlier tree does not verify a later edit.

## Read this evidence package

- [Sources and boundaries](sources.md): the six supplied documents, versions/digests, all ten Nielsen heuristics and dated-source conflicts.
- [Starting-point evidence](start-findings.md): role-aware next steps, empty access, record-derived progress and optional reading guidance.
- [Help evidence](help-findings.md): task guides, searchable glossary, public access, safe deep links and recovery wording.
- [Cash evidence](cash-findings.md): source timestamps/coverage, unavailable versus zero balances and accounting context.
- [Validation](validation.md): exact final source, integrated tests, before/after screenshots and journey checks, with explicit untested conditions.
- [Independent study protocol](research-kit.md) and [empty measurement template](measurement-template.csv): neutral tasks by actual role, unassisted/coached separation and proposed evaluation targets. Human usability acceptance is **not yet tested**.

The register below is the **single prioritised programme register**. The linked package notes retain detailed reproduction and test provenance; they are supporting evidence, not separate competing backlogs. Priority reflects task consequence, not measured frequency. Source inspection and synthetic engineering observations are labelled as such. Possible user misunderstandings remain hypotheses until an independent participant exhibits them.

## Navigation and vocabulary

Retain the current grouped navigation: Daily work; Customers and policies; Connected banking; Oversight; Setup and administration. **Overview** serves as Home without breaking existing URLs. Collections, Pay-by-bank, Credit Desk and Cash Desk retain their names and gain short task explanations. Shared Help is always reachable; contextual links choose the relevant guide, including the current Cash section, and return to that section. Page search searches names/descriptions only and cannot expose records.

Use specific outcome verbs and short explanations consistently:

| Existing concept | Beginner-facing explanation / boundary |
| --- | --- |
| Organisation / lender | Who owns this workspace and whose records are selected; selection does not grant access. |
| Reconciliation | Match payments to bills or repayments; retain the formal name in navigation and evidence. |
| Allocation | Apply a payment to a bill or repayment, subject to current Finance authority and remaining amounts. |
| Exception | An issue that needs review; resolving it does not itself refund or allocate money. |
| Mandate | Permission for recurring bank debits; separate from reading account data. |
| Save / check / commit | Saving and validating an import batch is not committing its rows. |
| Draft / review / approve | A maker's saved preparation still needs the required separate reviewer. |
| Pending / checking outcome / confirmed | A submitted request or browser return is not a confirmed receipt; unknown requires status recovery. |
| Assessment / recommendation / decision | Evidence and rule output support a qualified lender decision; they do not create one. |
| Bank timestamp / retrieval time | When the balance applies versus when the source was received; retrieval does not make it current. |
| Unavailable / zero | Missing or restricted evidence is unavailable; zero is a supplied numeric amount. |
| Accounting draft / export / posted | Preparation and download do not establish a verified accounting write. |
| VAT schedule / payroll export | Preparation is not tax filing or executed salary payments. |
| Reading tips / operational progress | Reading position can be remembered locally; task completion comes from server records. |

Secondary technical evidence remains available. Plain wording must not remove amount/currency, organisation/entity, source age, missing evidence, version, approval, consequence or a support reference needed for safe review.

## Controls preserved

Tenant/entity isolation and current server authority remain the boundary for all routes and actions. Guidance uses effective roles without assigning them. Financial/provider states, independent approvals, immutable history, original recovery keys, stale-version refusal and purpose-specific permissions are retained. No sensitive financial/applicant/payroll draft is added to browser storage.

The owner-approved PR #78 rule remains: new design-partner pricing uses reviewed contract dates; existing invoices and linked correction rates remain immutable. This programme changes no prices, contract dates, fees, eligibility, scheduling, billing or live activation rule. It adds no API contract, migration, provider integration or architecture rewrite.

A test-only fixture captures one default instant for `api.now` and scheduler timestamps, removing the previously recorded possibility that a simulated successful poll was newer than the failure a test had just arranged. It does not change production scheduling, weaken failed/recovered assertions or add retries to hide failures. Relevant final regression evidence belongs in validation.

## Remaining acceptance and release gates

Independent human orientation, unassisted task completion, critical comprehension and ease remain unmeasured. The research kit prepares that work; the CSV has no participant rows. Physical-device and screen-reader sessions must be reported separately from desktop browser emulation, jsdom and automated accessibility checks. The brief's one-minute, 90% and 4/5 targets are project proposals, not Nielsen standards or achieved results.

Controlled staff/invitation/MFA journeys, genuine two-person approvals, provider bank coverage and authorisation, legal/data permissions, external accounting writes, tax filing, payouts, independent alert delivery and hosted recovery require their own scoped evidence. Missing dependencies stay explicit; synthetic fallbacks do not become accepted live capabilities. No G0, G-DATA, G-CORE, G-OB, G-A2A, G-CREDIT, G-MODEL, G-AUTO, G-ERP, G-PAYOUT, G-TAX, FUND-M9, RECOVERY or PORTABILITY gate is advanced.

Before a release decision, inspect the exact candidate, final regression and journey results, source/claim consistency and any unresolved blockers in validation. This programme performs no merge, deployment, live permission change, real notification or financial activation. A later authorised publication needs its own exact-revision and live verification record.
