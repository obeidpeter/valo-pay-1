# Cash Desk source context

Scope: the existing Cash & forecast section at `/cash-desk`, based on PR #78 (`83eda41`). This is a bounded interface change. The existing consolidation service, permissions, timestamp validity, staleness budget, forecasting and financial rules are unchanged.

## Observed problems and dispositions

These are source and synthetic engineering findings, not observations of human participants. Consequences describe the possible misunderstanding to evaluate in the research study.

## Evidence

- Changed implementation: `artifacts/valo-pay/src/features/cash-desk/forecast-section.tsx` only.
- Existing authoritative data: `lib/valopay-schema/src/connected.ts` (`cashAccountSchema`, `cashPositionSchema`) and `artifacts/api-server/src/domain/connected-cash.ts` (`consolidateCashPositions`). No changes to these files.
- Added tests: `artifacts/valo-pay/tests/cash-source-context.test.tsx`. Four fixed-clock cases exercise the real page and domain-backed in-memory API.
- Before run: all four new cases failed because the expected source-context region was absent. This proves the baseline lacks the new context; it does not claim every later assertion was reached in that run.
- After run: the four added cases plus eleven existing `cash-desk.test.tsx` cases passed: **15/15**, two files, 18.11 seconds on the local Node 24.19 test runtime. The existing save/review, funding, permission and recovery cases were retained.
- Frontend production and test TypeScript checks passed with `tsc -p artifacts/valo-pay/tsconfig.json --noEmit` and `tsc -p artifacts/valo-pay/tsconfig.tests.json --noEmit`. The changed-file whitespace check passed.
- Raw local logs remain outside the repository under the task's `beginner-usability-2026-09-29` evidence directory as `cash-before.log` and `cash-after.log`. Browser layout, reflow and screenshots belong to the programme's separate browser evidence; jsdom tests do not establish physical-device or assistive-technology usability.

No sample source is described as live bank data. No retrieval is described as a completed financial close. No accounting post, permission change, provider request, financial instruction, merge or deployment was performed by this work. Independent human comprehension remains untested.
