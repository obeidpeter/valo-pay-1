The current GitHub rename guidance warns that reuse of the original name disables redirects, and that Pages and actions require separate handling. Repository-related OIDC subjects can change on rename; inspect the provider's actual subject/claims and trust before any repository name is reused. The checked-in CI requests `contents: read`, with no first-party `id-token: write` deployment workflow identified; that does not rule out external deployment authority. See [GitHub repository rename guidance](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository) and [OIDC reference](https://docs.github.com/en/actions/reference/security/oidc).
